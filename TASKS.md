# Refactoring Roadmap

Architecture cleanup for the Notes API, ordered so each step makes the next one easier.

| # | Task | Status |
|---|------|--------|
| 1 | Test isolation via dependency injection | ✅ Done |
| 2 | Remove `create_all`, let Alembic own the schema | ✅ Done |
| 3 | Centralize configuration | ✅ Done |
| 4 | Unique constraint on `users.name` | ✅ Done |
| 5 | Split routers, add prefixes and tags | ✅ Done |
| 6 | Extract a service layer | ✅ Done |

The numbered roadmap is complete. Remaining work is tracked under
[Smaller items](#smaller-items-no-particular-order) and [What's next](#whats-next).

---

## 1. Test isolation via dependency injection ✅

**Problem:** Tests ran against the development database (`authors.db`). `conftest.py` set
`DATABASE_URL`, but nothing read it — `session_factory` was a module-level global bound to a
hardcoded URL and imported directly into every endpoint. There was no seam to substitute.

**Done:**
- Added `get_session()` generator in `src/database/session.py`
- All 6 endpoints + `get_current_user` take `Annotated[Session, Depends(get_session)]`
- Removed every `with session_factory()` block from route bodies
- `conftest.py` registers `app.dependency_overrides[get_session] = override_get_session`

**Verified:** two consecutive runs, 7 passed each, `authors.db` never recreated.

**Concept:** an import is a hard-coded edge; a dependency is a swappable one. The seam only
works if the body has *no other way* to get a session — check that `session_factory` appears
nowhere outside `src/database/session.py`.

## 2. Remove `create_all`, let Alembic own the schema ✅

**Problem:** `main.py` called `Base.metadata.create_all(engine)` at import time *and* Alembic
migrations existed. Two sources of truth drift silently — a missing migration still "works"
locally, then breaks in production.

**Done:** deleted the `create_all` call from `main.py`. Tests still use `create_all` on their
own engine, which is a normal exception.

**Side benefit:** removed an import-time side effect, so module import order is no longer
load-bearing.

---

## 3. Centralize configuration ✅

**Problem:** three DB URLs that disagreed — `session.py` and `alembic.ini` both said
`sqlite:///authors.db`, `.env` said `notes.db` and was read by nothing. Plus
`os.getenv("JWT_SECRET_KEY")` returned `None` if unset, so AuthX would sign tokens with `None`
and fail at runtime instead of startup.

**Done:**
- Added `src/config.py` with a `Settings(BaseSettings)` class; `jwt_secret_key` has **no
  default**, so a missing value fails at import with a clear `ValidationError`
- `session.py` and `security.py` read from `settings`; dropped `load_dotenv()`
  (`env_file=".env"` replaces it)
- `alembic/env.py` calls `config.set_main_option("sqlalchemy.url", ...)` from the same settings
- Blanked `sqlalchemy.url` in `alembic.ini` so there's one source of truth
- Standardized on `sqlite:///./notes.db`

**Concept:** validate configuration at startup, not at first use. Fail loudly and early.

### Migrations were broken the whole time (found during this task)

`alembic upgrade head` failed with `no such table: authors`. The cause: **no migration ever
created `users` or `notes`.** The chain was leftover from an authors/books project —
`5b03552f3f1a` created `authors`/`books`, `e8426141a1bb` dropped them and ran
`add_column('notes', ...)` on a table Alembic had never made. It only ever worked because
`Base.metadata.create_all()` was silently building the real tables on startup. Removing that
in task #2 is what exposed it.

Root cause: `alembic/env.py` never imported the model modules, so `target_metadata =
Base.metadata` was empty and autogenerate wrote migrations from whatever stale schema it
could see.

**Fixed by:**
- Adding `from src.database.user import User  # noqa: F401` and the same for `Note` to
  `env.py` — the import *side effect* is what registers tables on `Base.metadata`.
  Keep the `noqa`; `ruff --fix` will otherwise delete them and silently break autogenerate.
- Squashing history: deleted both old versions, regenerated a single
  `79fa1774af32_initial_schema.py` from the live models.

**Verified:** `alembic check` → "No new upgrade operations detected."

⚠️ Rewriting migration history is normally forbidden — once a migration has run somewhere you
don't control, editing it means other environments can never reach the same state. It was safe
here only because there were no deployments and no real data, and the old files remain in git.

**Habit:** always read an autogenerated migration before applying it. It's a draft, not an
answer.

**Security (separate):** the real JWT secret is in git history at commit `eed96a2`
(`.env.example`). Commit `05564a3` replaced it going forward, but the old value is still
recoverable. Rotate the key if this repo is or will be public — deleting a secret in a later
commit does not unpublish it.

## 4. Unique constraint on `users.name` ✅

**Problem:** `signup` checked for a duplicate name in Python, but the DB accepted duplicates.
Two concurrent signups both pass the check and both insert. `login` uses `.first()`, so one of
those users could never log in.

**Done:**
- `name: Mapped[str] = mapped_column(String, unique=True, index=True)`
- Migration `9206b7f7623f` → `op.create_index(op.f('ix_users_name'), 'users', ['name'],
  unique=True)`
- `signup` catches `IntegrityError`, calls `session.rollback()`, returns 409

**Concept:** invariants belong in the layer that can actually enforce them. An application
check is a race; a database constraint is atomic. Both are kept on purpose — the check gives a
clean error in the common case, the constraint closes the race the check can't see.

**`session.rollback()` is mandatory.** After an `IntegrityError` the session is in a failed
state and every later operation raises `PendingRollbackError`. Since `get_session` hands out
one session per request, skipping the rollback would poison the rest of that request.

**SQLite note:** `batch_alter_table` was *not* needed here. `index=True` makes SQLAlchemy
express the constraint as a unique index (`CREATE UNIQUE INDEX`), which SQLite supports
natively. It would only be needed for a bare `unique=True`, which requires
`ALTER TABLE ADD CONSTRAINT` — something SQLite cannot do.

**Not tested, deliberately:** `test_signup_duplicate_user` exercises the Python check, not the
constraint. Actually testing the race needs concurrent requests, which isn't worth the
machinery here. The constraint's value doesn't depend on being tested.

## 5. Split routers, add prefixes and tags ✅

**Problem:** `endpoints/system/authors.py` held login, signup, and all note CRUD. Nothing about
it was "system" or "authors" — a leftover name from the old authors/books project.

**Final layout:**
```
src/api/
├── dependencies.py       get_current_user (shared, so it sits above the routers)
├── router.py             aggregates only — declares no routes
├── schemas/
└── endpoints/
    ├── auth.py           router = APIRouter(tags=["auth"])
    ├── notes.py          router = APIRouter(prefix="/notes", tags=["notes"])
    └── health.py         router = APIRouter(tags=["health"])
```

`main.py` now includes one `api_router`, so adding a resource touches `router.py` only.

**Organizing principle:** one router module per resource. Category folders (`system/`,
`common/`, `misc/`) don't survive a growing project — nothing tells you what belongs in them,
so everything does. Resource names answer "where does this go?" on their own.

**Each endpoint module is self-contained:** it creates its own `APIRouter`, declares routes
against it, and exports it. It imports *downward* (schemas, database, security), never sideways
or up. An `from main import ...` inside a leaf module is always a bug — it makes a cycle, and it
means you're missing an object that should be local.

**Kept behavior identical on purpose:** no `/auth` prefix, no `/api/v1`. Both are breaking URL
changes, and mixing them into a reorganization means a failing test can't tell you which change
broke it. Refactors and behavior changes belong in separate commits.

**Verified:** all 7 tests pass *unchanged*, and the OpenAPI paths match the original API
exactly — `/login`, `/signup`, `/notes`, `/notes/{note_id}`, `/health`.

**Also cleaned up:** deleted `/protected` scaffolding and the empty `system_router`; emptied the
`src/__init__.py` re-export so schemas import from `src.api.schemas.base` directly.

### Lint config added

`ruff check .` now passes clean. Two things needed help:

- `alembic/env.py` model imports carry `# noqa: F401` — ruff had flagged them, and
  `ruff --fix` would have deleted them and silently broken autogenerate a second time
- `src/database/{user,note}.py` use `if TYPE_CHECKING:` imports so the `Mapped["Note"]`
  forward references resolve for linters without creating a runtime circular import
- `pyproject.toml` ignores F401 under `alembic/versions/` — that boilerplate is generated

## 6. Extract a service layer  ✅

**Problem:** each endpoint does HTTP concerns (status codes, `HTTPException`), business rules,
and persistence in one function. You can't test "duplicate names are rejected" without an HTTP
client and a database.

**Done:**
```
router      → HTTP only: parse, call service, shape response
service     → business rules, knows nothing about HTTP
repository  → queries, knows nothing about business rules  (defer — likely premature here)
```

Services only. No repository layer — with four queries it would be ceremony.

**Concept:** recognizing when a pattern is *not* yet worth it matters as much as knowing it.

**Done:**
- `services/exceptions.py` holds `ServiceError` and its three subclasses. `main.py` maps them
  to 404 / 409 / 401, so status codes are chosen in exactly one place.
- `services/notes.py` and `services/auth.py` never import `HTTPException`. That's the test:
  if a service can't be called outside a request, the extraction isn't finished.
- `get_note_service` / `get_auth_service` inject a `Session`, so services reach the database
  only through the `get_session` seam. No new path to `session_factory`.
- `endpoints/` no longer imports `select`, `update`, `delete`, `Session` or `IntegrityError`.
  That import list going empty is the signal the move is complete.

**Verified:** the 7 pre-existing tests passed *unchanged*, and OpenAPI paths matched.

**The payoff:** `tests/test_services.py` — `pytest.raises(AlreadyExists)` around a duplicate
signup, with no `TestClient`, no app and no request. A business rule became testable in four
lines because it stopped being tangled with HTTP.

## Dependency hygiene (learned the hard way, tasks 3–4)

`alembic`, `pwdlib`, `fastapi`, and `uvicorn` were all imported by the code but missing from
`pyproject.toml`. Everything worked because they happened to be sitting in `.venv` — until the
first `uv add` re-synced the environment from the manifest and pruned everything undeclared.
Three separate `ModuleNotFoundError`s followed.

**A working venv is not a dependency list.** It accumulates whatever you've installed over
time. `pyproject.toml` is the contract; the venv is a cache of one interpretation of it. A
fresh clone would have failed exactly where these did.

**Rule: if you `import` it, declare it.** Relying on a transitive dependency (fastapi via
authx) means your build breaks when someone else refactors theirs.

To re-audit after any dependency change:

```bash
uv sync && pytest -q && alembic check
```

Also note `pwdlib` needs the `[argon2]` extra — `PasswordHash.recommended()` returns an Argon2
hasher, and the bare package doesn't ship the backend.

## Post-roadmap changes

### Fixed the `UpdatedNotes` response shape ✅

`PUT /notes/{id}` now returns the note; `DELETE` returns `204` with an empty body. `updated_rows`
was a SQLAlchemy `rowcount` — a driver artifact — leaking into the public contract, next to a
`success: true` that the `200` already implied.

`NoteService.update` uses `UPDATE ... RETURNING` to get the row back in one statement. The
obvious alternative, `UPDATE` then `SELECT`, is two round trips with a race between them.
SQLite has supported `RETURNING` since 3.35.

⚠️ Breaking change, kept in its own commit — see invariant 7.

### Added `POST /refresh` ✅

`login` had always returned a `refreshToken` that no endpoint accepted, so half the pair was
dead weight. With AuthX's default 15-minute access token, a client had no way back after expiry
except resending the password.

**Concept — why two tokens.** A JWT is stateless, so it cannot be un-issued; expiry is the only
control you have. One token forces a bad trade: long-lived is convenient but a leak lasts weeks,
short-lived is safe but unusable. Splitting by *how often each is transmitted* resolves it — the
access token goes everywhere so it expires in 15 minutes; the refresh token goes to one endpoint
so it can last 20 days.

- `AuthService.refresh` re-reads the user before minting. The refresh token outlives the row it
  names, and a signature can't know the account was deleted. That lookup is the business rule,
  and why this is a service method rather than a bare `create_access_token` in the endpoint.
- Both tokens arrive in the same `Authorization` header, so the `type` claim is the only thing
  separating them. `verify_type=True` is what stops a refresh token being used as a 20-day
  access token — `tests/test_auth.py` asserts both rejection directions, because those tests are
  the only record that the separation holds.
- No rotation and no logout. Revoking a JWT needs a denylist table, which is real storage. The
  short access-token lifetime *is* the revocation mechanism here.

## What's next

1. **Postgres in Docker.** The largest gap between this and a real backend. It will surface the
   SQLite assumptions that are currently invisible, and `batch_alter_table` stops being
   theoretical. `Settings` and the `%%` escaping in `alembic/env.py` are already braced for it.
2. **`created_at` + pagination**, in that order and *after* Postgres — so the first hand-written
   migration runs against a database you can't just delete. Pagination needs the timestamp
   anyway: without a stable `ORDER BY`, page boundaries are undefined and rows can repeat or
   vanish between pages.
3. **Add `mypy` to the verification triad.** It's declared but has never been run.

Deferred: async SQLAlchemy. It touches every layer at once, and the reason plain `def` is correct
here is already understood — the time would go on mechanics, not the concept.

## Smaller items (no particular order)

- `signup` has no `response_model`, so OpenAPI documents its response as `{}`. It returns a bare
  `{"success": true}` — the last of those left — and should be `201`, not `200`.
- `mypy` and `ruff` sit in main `dependencies`; they belong in the `dev` group. `uv sync --no-dev`
  currently ships a type checker to production.
- `Base` lives in `session.py`, but a declarative base isn't session machinery. Consider
  `src/database/base.py`.
- `LoginResponse` (`schemas/users.py`) redefines `model_config` and aliases. Pydantic v2 merges
  config across inheritance, and `BaseSchema`'s `alias_generator=to_camel` already produces
  `accessToken`/`refreshToken`. All three lines are redundant — `RefreshResponse`, added just
  below it, is the same thing written correctly.
- No pagination on `GET /notes`. Fine now; first thing to break at scale.
- `health` is `async def`, everything else is `def`. Both work — FastAPI runs sync endpoints in
  a threadpool. Plain `def` is *correct* here because SQLAlchemy is synchronous; a blocking call
  inside `async def` would freeze the event loop. Worth knowing why, it's a classic prod bug.

## What's already good — don't lose these

- `get_current_user` as a dependency: auth declared in the signature, not repeated per function
- Ownership enforced in the `WHERE` clause (`authors.py` update/delete) rather than
  fetch-then-check — atomic, and immune to a TOCTOU race
- `BaseSchema` with shared `model_config`: one place for serialization policy
- Tests cover the security property (`test_cannot_delete_others_note`), not just happy paths
- `pwdlib` with `PasswordHash.recommended()`, and identical error text for "no such user" vs
  "wrong password" — avoids user enumeration
